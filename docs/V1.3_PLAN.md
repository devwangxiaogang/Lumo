# 语光 Lumo 1.3 设计稿：多模型擂台 · 会话分支 · 双向同传 · 用量洞察

> 一句话：1.3 把「对话」从一条直线升级为**可比较、可分叉、可量化、可双向翻译**的工作台。
> 本文是架构与需求的唯一事实来源（single source of truth）。实现者只按本文与各自任务卡执行。

## 一、版本目标

| 目标 | 用户一句话 | 对应提案 |
|---|---|---|
| 多模型擂台 | 同一个问题，两个模型并排答，谁快谁好一眼看出 | FEATURES #4 |
| 会话分支 | 改一句话，从那里长出新分支，原答案保留 | FEATURES #6 |
| 面对面双向同传 | 手机放桌上，我说中文它翻英文，对方说英文它翻中文 | FEATURES #5 |
| 自动标题 + 用量洞察 | 列表能扫读；钱花在哪个模型上一眼看清 | FEATURES #9 / #10 |

不在本版范围：#7 MCP（安全模型未定）、#8 知识库（召回质量待验证）、#11/#12（需要新依赖/相机）。

### 硬约束（全版适用）

1. 不新增第三方依赖，不新增系统权限，不改 minSdk 24。
2. 免费档（Kilo 公共池 + 公开语音端点）必须优雅降级，不得因新功能崩溃或卡死。
3. 所有用户可见文案中英同步；本版采用**按功能拆分的资源文件**（见第八节），避免并行冲突。
4. 新功能一律「失败不影响主链路」：擂台单侧失败不影响另一侧，自动标题失败退回截断标题，统计只读。
5. 不改动 1.1/1.2 已上线行为（双档位、SSE、语音、翻译、备份、FTS）的语义。

## 二、架构总览

```
Compose UI            ChatScreen / ArenaScreen / TranslateScreen(FaceToFace) / UsageStatsScreen
   │  StateFlow / events
ViewModel             ChatViewModel / ArenaViewModel / TranslateViewModel / UsageStatsViewModel
   │
Repository / Service   ChatRepositoryImpl（消息图 + 生成）
                       ArenaRepositoryImpl（独立：并发双流 + 落库 + 投票）
                       AutoTitler（回合后置钩子，best-effort）
                       UsageStats（只读聚合）
   │
Data                   Room v6（messages.parentId / conversations.leafMessageId / arena_*）
                       SettingsRepository（autoTitleEnabled）
                       LlmProvider Map（复用现有四家，不新增网络层）
```

### 设计原则

- **接缝优先**：擂台是独立仓库 + 独立表，不进 ChatRepository 的生成循环；自动标题是「回合结束钩子」，失败静默；统计是只读 DAO。三者都不把 ChatRepositoryImpl 继续撑大。
- **消息图而非线性表**：分支用 `parentId` 表达树，会话用 `leafMessageId` 作游标。老数据迁移后自动变成单链，行为与 1.2 完全一致。
- **纯逻辑可测**：分支路径选择、擂台计时/胜负、标题清洗、统计聚合、双向语言判定全部抽成纯函数，配单元测试，不依赖 Android。
- **并行资源命名空间**：每个功能一对 `strings_<feature>.xml`，四人并行不碰同一文件。

## 三、数据模型 v6

### 3.1 新增列

```sql
ALTER TABLE messages ADD COLUMN parentId INTEGER NOT NULL DEFAULT 0;
CREATE INDEX index_messages_parentId ON messages(parentId);
ALTER TABLE conversations ADD COLUMN leafMessageId INTEGER NOT NULL DEFAULT 0;
```

含义：
- `messages.parentId = 0` 表示这是一条链的起点（通常是一条会话的第一条用户消息）。
- `conversations.leafMessageId` 指向当前激活分支的叶子；0 表示未初始化。
- 迁移时按 `(createdAt, id)` 顺序回填 parentId，并把 leafMessageId 置为会话最大消息 id，保证升级后历史窗口不变。
- 历史窗口 = 从 leaf 沿 parentId 回溯，再按时间正序、只取 `DONE` 状态。回溯由纯函数在内存完成（会话消息量级小，避免递归 CTE 的兼容性风险）。

### 3.2 擂台表

```sql
CREATE TABLE arena_runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  prompt TEXT NOT NULL,
  providerA TEXT NOT NULL, modelA TEXT NOT NULL,
  providerB TEXT NOT NULL, modelB TEXT NOT NULL,
  winner TEXT NOT NULL,          -- "" | "A" | "B" | "TIE"
  votedAt INTEGER NOT NULL,
  createdAt INTEGER NOT NULL
);
CREATE TABLE arena_outputs (
  id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  runId INTEGER NOT NULL,
  side TEXT NOT NULL,            -- "A" | "B"
  content TEXT NOT NULL, reasoning TEXT NOT NULL,
  status TEXT NOT NULL,          -- STREAMING | DONE | FAILED
  error TEXT NOT NULL,
  ttftMs INTEGER NOT NULL,       -- 首字延迟，0 = 未出字
  totalMs INTEGER NOT NULL,
  promptTokens INTEGER NOT NULL, completionTokens INTEGER NOT NULL,
  FOREIGN KEY(runId) REFERENCES arena_runs(id) ON UPDATE NO ACTION ON DELETE CASCADE
);
CREATE INDEX index_arena_outputs_runId ON arena_outputs(runId);
```

段位说明：擂台不写 messages/conversations，不污染会话列表与 FTS；历史在擂台页内查看，可删除。

### 3.3 设置项

`autoTitleEnabled`（默认 true，写入 SharedPreferences，不进 Room）。

## 四、工作流 A：多模型擂台（Arena）

### 用户故事
1. 列表页快捷入口「擂台」进入；顶部两个模型选择器（默认沿用上次选择的 A/B，首次为当前默认模型 + 另一服务商默认模型）。
2. 输入问题 → 「开战」→ 两栏并排流式输出；每栏实时显示 **首字延迟 / 输出 token / 估算费用**；单侧失败只影响该侧，另一侧继续。
3. 结束后可投「A 更好 / B 更好 / 平局」，投票写入 `winner`；可「再来一局」「清空历史」。
4. 历史列表按时间倒序展示过去的擂台局，点开回看完整双栏与投票。

### 交互与边界
- 输入为空不发；同一时刻只允许一局在跑（按钮转「停止」）。
- 免费档模型允许出现在任一侧；不校验 Key（复用 `ProviderConfig`）。
- 生图模型（`imageGen`）从选择器隐藏。
- 停止：取消两条协程，已生成内容按 DONE 落库（便于回看），未出字的一侧记 FAILED「已停止」。
- 空历史空态文案；最多保留 50 局，超出删除最旧（含 outputs 级联）。

### 实现契约
- `ArenaRepository`（domain 接口）+ `ArenaRepositoryImpl`（data，@Singleton，@Binds 注册）。
- `ArenaViewModel`：`StateFlow<ArenaUiState>`，字段：prompt、runs、activeRun（id + 两个 side 状态）、投票。
- 首字延迟用 `SystemClock.elapsedRealtime()`，从发起请求到第一个 `StreamEvent.Delta`；`ttftMs` 只在首次写入。
- token 取 `StreamEvent.Completed`；费用用 `ui/chat/UsageCost.formatCost` 同源规则（可在 arena UI 内调用公开函数，禁止复制价格表）。
- 单元测试：`ArenaTallyTest`（投票/胜负状态机、计时格式化、token 求和、超限淘汰）。

### 验收
- 两个不同服务商并排流式；断网时两侧均显示可读错误且可重开；投票后重进仍可见；历史超过 50 局自动淘汰。

## 五、工作流 B：会话分支（Branches）

### 用户故事
1. 长按**用户消息** → 「编辑并重新发送」：弹窗预填原文；发送后从该消息的父节点长出新分支，原分支完整保留。
2. 助手消息底部出现 `‹ 2/3 ›` 分支切换器（仅当该父节点下有多个助手回复时）：切换即切换当前激活路径，输入框与后续历史随路径变化。
3. 重试（已有按钮）在同一父节点下生成新的兄弟助手消息，旧回复不被删除，可用切换器找回。
4. 删除会话、导出 Markdown/HTML、ZIP 备份、FTS 正文检索对分支安全：导出只导出**当前激活路径**，备份导出全部消息并保留 parentId/leaf。

### 数据与算法
- 发送新消息：`parentId = 当前 leaf`（若会话无消息则为 0）；生成完成/失败后 `leafMessageId = assistantId`。
- 编辑用户消息：新用户消息 `parentId = 被编辑消息.parentId`，再生成其助手子节点；`leafMessageId` 指向新助手。
- 历史窗口：`BranchPath.resolve(messages, leaf)` 返回从根到叶的消息列表（含 FAILED 也保留链路，但发给模型的只取 DONE）。
- 分支切换器数据：`BranchPath.siblings(messages, targetId)` 返回同一 parentId 下同 role 的兄弟（按 createdAt,id 升序），并给出 index/size。
- 纯函数放 `domain/model/BranchPath.kt`，配 `BranchPathTest`：
  - 单链（老数据 parentId 全 0 + leaf=0）→ 返回全部消息；
  - 分叉 3 兄弟 → 只返回激活路径；
  - leaf 指向 FAILED → 祖先链完整；
  - 尺寸上限/环检测（脏数据 parentId 指回自己）不崩溃。
- 兼容：leafMessageId = 0 时按「全量线性」处理（迁移后不会出现，但导入备份/异常数据要兜底）。

### UI 契约（ChatScreen / ChatViewModel）
- 用户消息长按菜单新增「编辑并分支」（仅 DONE 且非生成中可用）。
- 助手消息操作行新增分支切换器（`Icons.AutoMirrored.Filled.KeyboardArrowLeft/Right`），文案 `branch_switcher` "2/3"。
- 编辑分支后清空输入框、滚动到底、停止朗读。

### 验收
- 老会话升级后历史、重试、导出与 1.2 一致；
- 同一用户消息下 3 条助手回复可来回切换，历史与 token 统计随路径一致（token 显示按当前消息本身，不做会话累计修改）；
- 导出/备份/搜索不丢消息；单元测试全绿。

## 六、工作流 C：AI 自动标题 + 用量洞察

### C1 自动标题
- 时机：会话**首轮成功**（第一条助手消息 DONE）后异步触发，仅当标题为空/旧版「新对话」。
- 方式：复用当前会话 provider/model 发一次低预算请求（`maxOutputTokens = 32`），提示词要求「6-12 字标题，不要引号/标点/解释」。
- 清洗：`AutoTitle.clean(raw)` 去引号、去换行、去「标题：」前缀、截断 24 字符；空结果 → null 不写入。
- 开关：设置 → 语音与朗读页（或数据组）新增「AI 自动标题」开关，默认开；关闭后仅保留首条消息截断标题。
- 失败/超时（8s）/免费档 429 → 静默；不打断对话、不消耗主请求轮次。
- 纯函数测试：`AutoTitleTest`（围栏、引号、中英混合、超长、空串、含冒号）。
- 由 `ChatRepositoryImpl` 的回合结束钩子调用 `AutoTitler.maybeTitle(conversationId, provider, model)`（钩子已在 1.3 基础层预埋）。

### C2 用量洞察
- 入口：设置 → 数据组「用量统计」。
- 内容：总 token / 估算总费用 / 会话数；近 14 天柱状（输入+输出堆叠）；按模型 Top 8 排行（模型、token、费用）。
- 数据：只读聚合 `StatsDao`（已预置），费用用 `estimateCost(provider, model, prompt, completion)`；免费档恒 ¥0.00；未知模型显示「—」。
- 空态：没有任何用量时显示引导文案，不画空图。
- Canvas 手绘柱状，不引入图表依赖；深色模式适配。
- 测试：`UsageAggTest`（按天补零、Top 排序、费用汇总、空数据）。

### 验收
- 首轮对话结束后列表标题在 2-5 秒内变成语义标题；关闭开关后不再请求；
- 统计页数字与消息详情里的 token 一致；无数据时不崩溃。

## 七、工作流 D：面对面双向同传（Face-to-Face）

### 用户故事
1. 翻译页新增「面对面」模式（与 同传 / 文字 / 图片 并列）。
2. 上下两块大卡：上方对方（外语），下方我方（中文）；每句话自动判语种，翻向另一边并朗读目标语。
3. 顶部两个语言胶囊可手动锁定方向；「自动」为默认，按识别文本脚本判定。
4. 复用现有麦克风权限与 VAD 分段链路；免费档走「识别 → 翻译 → 朗读」流水线，收费档复用 AST（方向切换时重建会话并显示「正在切换方向」）。

### 数据与算法
- `FaceDirection.detect(text, fallback)`：CJK 比例 → zh，拉丁 → en，其余按 fallback；连续两句同向不重复切换（滞回）。
- `FaceTurn` 模型：side（ME/OTHER）、sourceText、targetText、langFrom、langTo、createdAt。
- 结束或切页时把整段对话作为一条 `translations` 记录（kind = "FACE"，sourceText/targetText 用换行拼接，option 记语对）——复用现有记录页。
- 纯函数测试：`FaceDirectionTest`（中文/英文/数字/混排/空串、滞回、非法语种兜底）。

### UI 契约
- 新文件 `ui/translate/FaceToFaceStage.kt`，由 TranslateScreen 增加一个 tab 分支调用（D 可最小改动 TranslateScreen 的 when 与 tab 列表）。
- 不新增长按/手势依赖；按钮语义与现有 Live 模式一致（开始/结束/换向）。

### 验收
- 中英往返各说一句，上方卡片出英文原文+中文译文、下方出中文原文+英文译文，各自朗读；
- 免费档不可用语言对时给出与现有免费同传一致的提示；切页自动结束会话并落一条记录。
