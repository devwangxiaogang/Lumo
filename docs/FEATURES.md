# 语光 Lumo · 有趣功能提案（2026-11）

> English abstract: a code-grounded feature slate for Lumo, an offline-first Android AI assistant. Each item lists user value, effort, risk and the exact modules it touches; the v1.2 batch shipped in this repository is marked ✅.

## 一、现状：已经有什么

| 能力 | 现状 | 代码位置 |
|---|---|---|
| 对话 | 流式 SSE、思考折叠、Markdown、重试/复制/朗读、人设、模型目录 | `app/src/main/java/com/yuguang/lumo/data/ChatRepositoryImpl.kt`、`ui/chat/` |
| 双档位 | 收费（豆包/方舟）与全链路免费（Kilo 公共池 + 公开语音端点） | `domain/model/Speech.kt`、`data/SpeechRouter.kt` |
| 语音 | 端到端实时语音（Seeduplex）、同传、朗读、识别、免费降级链路 | `data/remote/`、`data/SpeechReader.kt`、`ui/voice/` |
| 翻译 | 文字翻译、同声翻译、记录分组搜索 | `ui/translate/`、`data/local/TranslationStore.kt` |
| 工具 | `get_time / calculate / fetch_url（含 SSRF 防护）/ search_my_chats`，最多 3 轮 | `data/ToolRegistry.kt`、`ChatRepositoryImpl.kt:414` |
| 记忆 | 回合结束提炼偏好，本地去重存储，默认关闭 | `data/MemoryStore.kt` |
| 数据 | Room v5、FTS4 全文索引、ZIP 备份、Markdown/HTML 导出 | `data/local/`、`data/ChatBackupManager.kt` |

已经做得比较满：多服务商、双档位、语音全链路、本地工具与记忆都在。所以「有趣」不等于「再堆一个聊天框」，而是**补上体验断点**（朗读要等整段、动作要翻三层菜单、图片里的字用不上）与**打开新玩法**（多模型对比、双向同传、知识库）。

## 二、评价标准

- **价值**：用户能否在一句话里说出「这个有意思」。
- **工作量**：改动文件数与是否需要数据库迁移；小 ≈ 1 屏代码，中 ≈ 1 个 ViewModel + 1 个页面，大 ≈ 新模块或新依赖。
- **风险**：是否依赖不稳定的免费端点、是否引入权限/依赖、是否会破坏现有双档位语义。
- 硬约束：不新增第三方依赖（除非说明）、不新增系统权限、免费档必须能优雅降级、中英文案同步。

## 三、候选清单

### ✅ 1. 边生成边朗读（v1.2 已实现）

**一句话**：回复还在流式输出时，就按句合成播报，不必等整段结束。

- 价值：语音场景的核心体验；长回答的等待从「十几秒」变成「一句话」。
- 做法：`SpeechSplitter` 把增量切成 40–300 字的句子（跳过代码块、不切小数），`StreamingSpeaker` 逐句走现有三条 TTS 链路；`SpeechPreferences.autoRead` 开关，默认关闭。
- 风险：豆包按句合成会增加请求数；免费端点可能限速——已在切句时合并短句、失败静默降级到本机朗读。

### ✅ 2. 斜杠指令面板（v1.2 已实现）

**一句话**：在输入框打 `/draw`、`/translate`、`/summary`、`/model`、`/voice`、`/new`、`/help`，客户端直接执行，不浪费一轮额度。

- 价值：把藏在三层菜单里的动作变成一行文本；对重度用户是效率，对新用户是「原来还能这样」。
- 做法：`domain/ChatCommand.kt` 纯解析 + `ChatScreen` 输入前缀触发的面板；导航与预填沿用现有路由与新增的 `TranslateSeedBus`。
- 风险：以 `/` 开头的普通文本被误判——只有首词命中命令表才拦截，其余原样发送。

### ✅ 3. 图片文字翻译（v1.2 已实现）

**一句话**：相册选一张菜单/路牌/说明书，逐行给出原文与译文，可复制可朗读。

- 价值：和已有的同传、文字翻译组成完整链条；旅行场景最实用。
- 做法：`PhotoTranslator` 用一次视觉模型请求拿 JSON 行对，`PhotoLines.parse` 容错解析，结果写入 `translations` 表（`kind = PHOTO`）。
- 风险：OCR 质量取决于视觉模型；免费档用 Kilo 池，UI 明示试验级并可退化为整段译文。

### ✅ 4. 多模型擂台（v1.3 已实现）

**一句话**：同一个问题，两个模型并排流式作答，实时显示首字延迟、token 与估算费用，最后可投票。

- 价值：项目已经有四个服务商，「谁更快更准」是天然的好奇点；也是自媒体传播点。
- 做法：`arena_runs` / `arena_outputs` 两张表（v6 迁移），`ArenaRepositoryImpl` 用 `supervisorScope` 起两条独立流、各写各的 output；投票存 `winner`（A / B / TIE）。
- 实测结论：免费池与 DeepSeek 并排可用；**「首字」按第一次有输出（思考或正文）计时**，否则思考型模型永远显示「—」。

### ✅ 5. 面对面双向同传（v1.3 已实现）

**一句话**：上下两块大卡，每句话自动判语种并翻向另一边，说完即播报。

- 价值：同传现在是「单向固定语对」，双向才是旅行对话的真实形态。
- 做法：免费档的 VAD 流水线天然支持逐段换向；收费档 AST 的语对固定，切向需重建会话（约 1 次重连，UI 提示「正在切换方向」）。
- 风险：方向切换带来的延迟；需要在 `TranslateViewModel.toggleLive` 之外拆出可重建的会话管理。

### ✅ 6. 会话分支 / 编辑重发（v1.3 已实现）

**一句话**：改一条用户消息，从那里长出新的分支，原分支保留。

- 价值：把「重试」升级为「探索」；对写代码/写文案的用户尤其有用。
- 做法：`conversations` 或 `messages` 加 `parentId`，历史窗口按当前分支回溯；UI 长按用户消息「编辑并分支」。
- 风险：分支与现有 `retry`、备份导出、FTS 的交互都需要覆盖测试。

### 7. MCP 客户端

**一句话**：填一个 MCP 服务地址，把它暴露的工具接进现成的工具轮次。

- 价值：不写代码就能给助手加能力（文件、日历、内部系统），是「工具」这条线最有想象力的延伸。
- 做法：JSON-RPC 2.0 over HTTP/SSE（项目已有 `SseDecoder`），把 `tools/list` 转成 `ToolSpec`，`tools/call` 走 `ToolRegistry.execute` 的同一分支。
- 风险：远程代码执行面、超时与鉴权；需要白名单与开关，默认关闭。

### 8. 本地知识库（RAG）

**一句话**：导入 txt/md，按关键词与字符二元组召回片段，注入 system。

- 价值：让「我的资料」参与对话，且完全本地、不需要向量服务。
- 做法：新表 `documents` / `chunks`，切块后与 `MemoryStore` 同款注入；检索先用 BM25 简化版或字符二元组打分。
- 风险：召回质量不如向量检索；需要明确「引用了哪些片段」的 UI 以建立信任。

### ✅ 9. AI 自动标题（v1.3 已实现）

**一句话**：首轮结束后用一次低预算请求生成 6–10 字标题。

- 价值：列表页现在取首条消息前 24 字，长问题会很难认；自动标题让历史可扫读。
- 做法：复用 `MemoryStore.extract` 的低预算请求模式，失败保留现有截断标题。
- 风险：多一次请求与费用；免费档可只在本地截断，或作为可选开关。

### ✅ 10. 使用统计仪表盘（v1.3 已实现）

**一句话**：按天 / 模型 / 会话画 token 与费用趋势。

- 价值：数据已经在 `messages.promptTokens/completionTokens` 里，只是没被看见。
- 做法：新页面读聚合查询，Canvas 手绘折线/柱状；不需要新依赖。
- 风险：低；主要是聚合查询与空数据态。

### 11. 桌面小组件 / 快捷磁贴

**一句话**：桌面一键进语音或开新对话。

- 价值：把「打开 App 再点两下」变成一次点击。
- 风险：需要新依赖（Glance）与 AppWidget 配置，minSdk 24 要兼容；列入依赖评估。

### 12. 拍照实时覆盖翻译

**一句话**：相机取景，译文直接叠在原文位置。

- 价值：最直观的「AI 相机」体验。
- 风险：需 CameraX + 文字框排版，工作量大；与 #3 共用 OCR 与翻译后端。

## 四、分批建议

- **v1.2（本仓库已实现）**：#1 边生成边朗读、#2 斜杠指令面板、#3 图片文字翻译。三项都不加依赖、不加权限，覆盖免费/收费两档。
- **v1.3（本仓库已实现）**：#4 多模型擂台、#5 面对面双向同传、#6 会话分支、#9 AI 自动标题、#10 用量统计。设计稿与验收见 `docs/V1.3_PLAN.md`、`docs/V1.3_REPORT.md`。
- **观察名单**：#7 MCP 客户端（想清楚安全模型再做）、#8 知识库（先验证召回质量）、#11/#12（需要新依赖）。

## 五、已知取舍

- 流式朗读按句合成，句子之间可能有百毫秒级空隙；这是「先听到」与「完全连续」之间的取舍，已通过合并短句缓解。
- 图片翻译依赖视觉模型，不是专用 OCR；免费档质量明显低于收费档，UI 会标注实际使用的模型。
- 斜杠指令只在客户端解释，不进入模型上下文——模型不会「看到」这些命令，也不会因此多消耗 token。
